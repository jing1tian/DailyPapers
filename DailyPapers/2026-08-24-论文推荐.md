### 2. EnvHarness: Awakening Static Worlds for Agent Learning
- **作者**: Huang, Chengsong; Wang, Zifeng; Han, Rujun; Yan, Jun; Chen, Yanfei; 等（Google 团队）
- **机构**: 未知（arXiv 原始数据）

> ⏪ **再推提醒**：这篇在 2026-08-22 推荐过

- **核心方法**: EnvHarness 是套在静态 benchmark 环境外面的可编程插件层，不改动底层 verifier，通过标准接口注入行为：观察 agent 的执行轨迹，诊断失败模式，自动合成针对性的环境变体（即 EnvHarness 组件），然后用 fresh rollout 验证有效性。EnvRigger 是负责自动化诊断 + 合成的子模块，把目标 policy 当作黑盒。整套流程最终给 RL 提供比静态 env 质量更高的优化信号，无需重写 benchmark 逻辑。

### 6. 4DAnyone: Create Anyone in 4D from a Casual Monocular Video
- **作者**: Yudong Jin, Tao Xie, Qihang Zhang, Zehong Shen, Zhen Xu, Yujun Shen, Hujun Bao, Xiaowei Zhou, Yinghao Xu
- **机构**: State Key Lab of CAD&CG, Zhejiang University; Hong Kong University of Science and Technology; Chinese University of Hong Kong
- **链接**: [arXiv](https://arxiv.org/abs/2608.20335) | [PDF](https://arxiv.org/pdf/2608.20335)
- **来源**: 🔥 HF Trending，⬆️ 69

> ⏪ **再推提醒**：这篇在 2026-08-22 推荐过

![](https://arxiv.org/html/2608.20335v1/teaser.png)

- **核心方法**: 输入单目 RGB 视频，输出 4D Gaussian Splatting（4DGS）重建结果。核心挑战是 camera-controlled 视频扩散模型在生成大量多视角一致视频时跑不动——DiT 单次 forward 处理视角数有限，拆组之后跨组信息断裂。论文提出两个互补设计：Reference Context Packing（RCP）把越来越多的 reference views 压缩成固定长度的 mixed-resolution context，把 reference 侧的计算复杂度从 O(N) 降到 O(1)；Target Context Routing（TCR）在去噪过程中旋转 target view 分组，高噪声阶段跨组共享 context，低噪声阶段稳定细节。还构建了 MVGameHuman 游戏引擎数据集用于训练。
- **对比方法/Baselines**: 与 [[ReCamMaster]]、[[TrajectoryCrafter]]、[[CameraCtrl]]、[[SynCamVideo]] 对比。在 DNA-Rendering 和 DyMVHumans benchmark 上评测。
- **借鉴意义**: RCP 的 reference context 压缩思路对任何需要处理大量 reference views 的扩散任务都有参考价值，比如 novel-view synthesis 或 scene reconstruction。4DGS 与 human motion capture 的结合路线，对需要获取 4D 人体姿态数据的 imitation learning 场景有价值。
- **锐评**: 技术路线扎实，bounded-attention-context 的问题定义很清晰，RCP+TCR 的解法也合理。但 has_real_world=false，实验全在合成/光场数据集上（DNA-Rendering、DyMVHumans），对 in-the-wild monocular video 的鲁棒性只有 qualitative 展示。游戏引擎合成数据 MVGameHuman 能弥补多少真实分布的 gap 还不清楚。69 upvotes 说明热度中等，不算这周的顶流。 👀

## RL / 验证

### 7. LLM-as-a-Verifier: A General-Purpose Verification Framework
- **作者**: Jacky Kwok 等
- **机构**: Stanford University; UC Berkeley; NVIDIA Research
- **链接**: [arXiv](https://arxiv.org/abs/2607.05391) | [PDF](https://arxiv.org/pdf/2607.05391)
- **来源**: 🔥 HF Trending，⬆️ 18

> ⏪ **再推提醒**：这篇在 2026-08-19 推荐过

![](https://arxiv.org/html/2607.05391v2/figures/SOTA.png)

- **核心方法**: 传统 LLM judge 输出离散分数，LLM-as-a-Verifier 改为对 scoring token 的 logit 分布取期望，得到连续置信度分数。这个概率化表达式允许沿三个维度 scaling：(1) 评分粒度（细化分档让正负样本分离更好）；(2) 重复评估（减少方差）；(3) 标准分解（将复杂判断拆成子标准，逐一评分再合并）。另外设计了 Probabilistic Pivot Tournament（PPT）算法，用连续分数做候选解 ranking，节约验证 budget。在 RL 中作为 dense reward 信号，在 [[SAC]] 和 [[GRPO]] 上提升了样本效率。
- **对比方法/Baselines**: Terminal-Bench V2（86.5%）、[[SWE-Bench]] Verified（78.2%）、RoboRewardBench（87.4%）、MedAgentBench（73.3%）。对比了标准 LM judge、基于规则的 verifier。对 robotics 专门有 [[LIBERO]] 上的 RL 实验。
- **借鉴意义**: RoboRewardBench 87.4% 说明这个 verifier 在 robotics preference data 上确实比训练过的专用模型还强。用它给 robot RL 提供 dense reward 有实际价值，特别是无法手写 reward function 的任务。连续分数比离散标签对 RL 更友好这个点本身不新鲜，但把 logit 分布作为概率估计的工程实现细节值得参考。
- **锐评**: 18 upvotes 惨得可以，这篇的真实水平比曝光度高很多。RoboRewardBench 的结果是亮点——打赢了专门为机器人训练的 reward model。但 "general-purpose" 这个 claim 站不站得住取决于 terminal/coding 任务和 robotics 任务有没有用同一套配置，摘要没说清楚这里有没有 task-specific tuning。PPT 的预算-精度 trade-off 数据有展示，但实际 token 消耗没给出来，成本是否可接受需要自己计算。 👀
