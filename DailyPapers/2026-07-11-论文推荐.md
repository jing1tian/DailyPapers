- **作者**: (Georgia Institute of Technology)
- **机构**: Georgia Institute of Technology
- **链接**: [arXiv](https://arxiv.org/abs/2607.08436) | [PDF](https://arxiv.org/pdf/2607.08436)
- **来源**: 📄 arXiv 关键词检索

![](https://arxiv.org/html/2607.08436v1/x1.png)

- **核心方法**: EgoWAM 质疑 behavior cloning 从 egocentric 人类视频迁移到机器人的根本假设。问题是：BC 把"哪个物体在哪"和"人的手怎么动"纠缠在一起；WAM 的解法是同时预测 action + 未来帧（像素/表示），逼迫网络学到可迁移的 task semantics 而非 human morphology。输入：egocentric 视频（从野外数据集 EgoVerse 等采集），输出：机器人动作 + 未来帧预测。关键组件：DiT-based 联合预测 head + co-training with real robot data；核心区别在于 WAM 目标函数天然分离 "what to do" 和 "how the human does it"。
- **对比方法/Baselines**: 对比了 [[BC]]、[[ACT]] 等纯 behavior cloning 基线；借鉴了 [[DiT]]、[[RoboTwin]] 作为评估环境；世界模型侧参考了 [[DDT]] 框架。
- **借鉴意义**: 如果你在用人类 egocentric 数据训练机器人策略，这篇提供了一个比 BC 更好的监督信号框架。WAM co-training 的设置值得直接拿来用。
- **锐评**: 核心 insight 清晰——WAM 目标比 BC 分离得更干净。`has_real_world=True` 说明有真实机器人实验，不是 sim-only。美中不足：EgoVerse 数据集的 domain gap 具体有多大、不同 morphology 下迁移率是否稳定，摘要没有给出量化。"beyond pixels" 的 claim 比较大，但方向踩对了。🔥

- **机构**: Shanghai University of Finance and Economics

- **核心方法**: 论文质疑了主流范式——直接把 LLM/VLM 梯度注入 robot world model 的 discrete symbol system（RT-2、Octo、PaLM-E 都这么干）。发现问题：language gradient 会覆写物理符号表示。解法：write-protected discrete bottleneck（GumbelBottleneck），language 只能读不能改 physical representation；双引擎架构分离语言梯度和物理动力学学习。输入：语言指令 + 视觉观测，输出：预测的世界状态 + action。在 [[MuJoCo]] 上有真实实验（`has_real_world=True`）。

- **借鉴意义**: 做 language-conditioned world model 或 VLA 的人必须看这篇。write-protected bottleneck 的 architectural constraint 可以直接嫁接到现有框架。
- **锐评**: 问题陈述非常清晰，对 end-to-end language injection 的质疑有理有据。但来自上海财经大学而非主流机器人 lab，工程实现可信度需要验证；`has_real_world=True` 但 MuJoCo 毕竟是仿真，实体机器人上的表现摘要未提及。是一篇 idea 很好的工作，落地的关键在于 discrete symbol 的表示容量够不够。🔥

### 8. V-VLAPS: Value-Guided Planning for Vision-Language-Action Models
- **作者**: (机构未知)
- **机构**: 未知
- **链接**: [arXiv](https://arxiv.org/abs/2601.00969) | [PDF](https://arxiv.org/pdf/2601.00969)
- **来源**: 📄 arXiv 关键词检索

![](https://arxiv.org/html/2601.00969v3/VVLAPS.png)

- **核心方法**: 现有 VLA-guided planning（如 VLAPS）在 tree search 的 node selection 上过度依赖 policy prior 和 visit count，忽略了真正的 value 估计。V-VLAPS 引入显式 value function 指导 PUCT 公式，在 [[AlphaGo]] 式 MCTS 框架下做 VLA planning。输入：当前观测 + 任务语言描述，输出：经 value-guided tree search 选出的 action sequence。与 UVLAPS 对比，核心区别是 value head 的引入使搜索更关注 long-horizon 任务结构而非局部 policy 置信度。
- **对比方法/Baselines**: 直接对比 [[UVLAPS]]（前版本）和 [[AlphaGo]] MCTS；测试在 [[LIBERO]] benchmark 上，`has_real_world=False`——只有仿真实验。借鉴 [[PUCT]] 公式和 [[SAFE]] 约束。
- **借鉴意义**: VLA + planning 的组合对 long-horizon 任务至关重要。value function 的引入是 non-trivial 的改进，值得在自己的任务上复现。
- **锐评**: 思路对——value guidance 确实比纯 policy prior 更稳健。但 `has_real_world=False`，只在 LIBERO 仿真上做了实验；LIBERO 的 task 太短了，long-horizon 优势能不能在 real robot 复现存疑。MCTS 的计算开销在 real-time robot control 场景是硬伤，摘要没有谈推理速度。🔥

- **对比方法/Baselines**: 与 [[LIBERO]]、[[CALVIN]]、[[DexMimicGen]] 等现有 benchmark 对比设计维度；评测了 [[OpenVLA]]、[[DP]] 等策略。
- **借鉴意义**: 如果你需要一个灵巧操作 benchmark，DexVerse 的 100 任务规模和多体身支持比 LIBERO 更全面。数据集可能直接拿来用。
- **锐评**: 又一个灵巧操作 benchmark，来自 UNC+HKU+UCB 联合组，背书还行。100 任务数量可观，但仿真 benchmark 的问题在于 sim-to-real 转移——没有真实机器人评测，实际部署价值未知。Modular 设计理念好，但可控视觉变化是否真的 cover 了 real-world 的 distribution shift 需要验证。💤

### 15. GIRAF: Towards Generalizable Human Interactions with Articulated Objects
- **作者**: (机构未知)
- **机构**: 未知
- **链接**: [arXiv](https://arxiv.org/abs/2607.07880) | [PDF](https://arxiv.org/pdf/2607.07880)
- **来源**: 📄 arXiv 关键词检索

![](https://arxiv.org/html/2607.07880v1/figs/fig2-min.png)

- **核心方法**: 合成全身人类与关节物体交互（articulated objects，如抽屉、剪刀、门）的运动，用于 embodied AI 训练数据生成。输入：3D 场景 + 物体关节状态，输出：全身 SMPL 人体动作轨迹。通过 FiLM 条件化机制 + SDF 约束保证接触合理性。数据集：[[ARCTIC]]、[[GRAB]] 等 HOI 数据集。

- **锐评**: 应用方向对（embodied AI 数据生成），但离机器人控制还差一步——合成的是人类运动而非机器人动作，morphology gap 没有解决。Sim-only，没有真实验证。对做 motion retargeting 研究的人有用，对直接做机器人 policy 的人间接价值为主。👀

## 今日趋势判断

今天最值得关注的趋势：**WAM 训练信号的重构**（EgoWAM 用 egocentric data 训练 WAM）和 **language-physical 接口的架构化思考**（Write-Protected WM 质疑端到端注入的安全性）。这两篇都在问"现有范式对不对"而不是"如何做更大"，这是质量论文的典型特征。VLA 侧的 V-VLAPS 把 value function 引入 tree search 也是正确方向，但 real-world 验证的缺失是硬伤。整体而言，今天比上周灌水少，LingBot 家族的批量产出值得关注（他们在同时推进 VLA+WM+Video 三条线）。
