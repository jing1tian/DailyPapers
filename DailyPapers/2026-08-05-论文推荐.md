## World Action Models

### 1. Faster-WAM: Do World Action Models Need Deep Action Modules?
- **作者**: Liheng Ma et al.
- **机构**: Huawei Noah's Ark Lab, Huawei Celia Team, Department of Foundation Model 2012 Labs
- **链接**: [arXiv](https://arxiv.org/abs/2608.02365) | [PDF](https://arxiv.org/pdf/2608.02365)
- **来源**: 📄 arXiv 关键词检索

![](https://arxiv.org/html/2608.02365v1/x1.png)

- **核心方法**: 提出 DoT（Dock of Transformer）——把预训练视频 Transformer 当作固定的表征枢纽（hub），在其外部对接若干轻量独立的动作解码器，而不是把动作模块深埋进视频 backbone 的每一层。输入为视频帧序列，输出为机器人动作块；轻量动作解码器只需读取视频 backbone 的最终 token，无需在 backbone 深层共享参数。与 [[MoT]]（Mixture-of-Transformers）和 shared-backbone WAM 的本质区别：后者把动作模块深度绑定在视频 backbone 深度上，导致计算量随 backbone 规模线性增长。DoT 完全解耦，动作模块可以极浅。
- **对比方法/Baselines**: 与 [[MoT]] 架构、共享 backbone 的 WAM 方案对比，在 [[RoboTwin]]（仿真）和 [[LingBot-VLA-2.0]]（真实机器人）上评估。
- **借鉴意义**: 如果你在做 WAM 系列工作，DoT 是降低推理延迟的直接方案。轻量解码器意味着更快的控制频率，这是 real-time 操作的硬需求。
- **锐评**: Huawei Noah's Ark 今天给出了今日最有价值的架构贡献。"动作模块需要跟视频 backbone 一样深吗"——这个问题问得好，答案是不需要。DoT 的思路干净，但有个隐患没说清楚：轻量解码器如果信息不够，会不会在复杂接触任务里翻车？论文测的 RoboTwin 和 LingBot 任务并不是高精度接触场景，真正的 dexterous manipulation 表现摘要未提及。另外，DoT 的计算节省有多少来自解耦、有多少只是因为参数更少——这个 ablation 是否彻底，需要看全文确认。 🔥

### 2. SelfWAM: A Self-Grounded Unified World Action Model for Fast Robot Control
- **作者**: Bikang Pan et al.
- **机构**: 未知
- **链接**: [arXiv](https://arxiv.org/abs/2608.00725) | [PDF](https://arxiv.org/pdf/2608.00725)
- **来源**: 📄 arXiv 关键词检索

![](https://arxiv.org/html/2608.00725v1/x1.png)

- **核心方法**: SelfWAM 在 [[MoT]] 架构上构建统一框架，联合预测动作和**以动作为条件**的未来 RGB 帧（action-conditioned future frames），而非只以任务目标为条件。"自接地"的关键：世界模型的未来预测显式依赖 WAM 当前输出的动作，使视觉预测与实际执行动作保持语义一致。输出：动作块 + 预测帧。在 [[RoboTwin]] 和 [[ALOHA]] 上有真机实验。
- **对比方法/Baselines**: 对比 ImageWAM、MaskWAM、GeoSem 等 WAM 变体；基础设施使用 [[GigaWorld1]] 预训练权重；AgileX 真实机器人。
- **借鉴意义**: action-conditioned future prediction 而非 task-conditioned 是个重要区分，值得关注。如果你在做 WAM，SelfWAM 的自接地 loss 设计可以直接参考。
- **锐评**: 思路清晰，"以动作为条件预测未来"这个 inductive bias 确实合理。但 method_summary 为空，可能意味着论文写作上方法描述不够完整，需要看全文确认架构细节。有真实机器人实验是加分项。主要问题：与同期大量 WAM 工作（尤其是 [[MoT]] 系列）的区分度是否足够明显，还是只是在 MoT 框架上加了一个 action conditioning loss？ 🔥

### 3. SG-WAM: Self-Guided World Modeling in Geometry-Aware Policy Space
- **作者**: Ruiteng Zhao, Zhengshen Zhang, Yue Su, Wenshuo Wang, Jiahui Li, Zhiyuan Yang, Francis E. H. Tay, Marcelo H. Ang Jr., Haiyue Zhu
- **机构**: 未知（NUS 机器人研究所，Marcelo Ang 组）
- **链接**: [arXiv](https://arxiv.org/abs/2608.01397) | [PDF](https://arxiv.org/pdf/2608.01397)
- **来源**: 📄 arXiv 关键词检索

![](https://arxiv.org/html/2608.01397v1/x1.png)

- **核心方法**: 核心问题：现有 WAM 要么在像素空间建模（计算重），要么用任意 latent（与动作不对齐）。SG-WAM 引入**几何感知 policy space**（SGWP）：用 [[VGGT]] 提取几何结构作为空间锚点，在 [[JEPA]] 风格的 latent 空间中预测未来状态，同时该 latent 被明确约束为"对动作生成有用"的表征。输入：当前 RGB 帧 + 几何特征；输出：latent 预测 → 动作块。与 UniPi、WorldVLA 等的区别：既有几何结构又有动作对齐，不用生成像素。
- **对比方法/Baselines**: 对比 [[OpenVLA]]、[[UniVLA]]、WorldVLA、OFT；LIBERO 基准；RealSense 真实机器人。
- **借鉴意义**: 几何感知 + JEPA 风格的结合是一个值得关注的方向，特别是对于需要精确空间推理的操作任务。
- **锐评**: Marcelo Ang 组的工作通常有工程实力保底，这篇也不例外。几何感知 policy space 的想法优雅：既解决了像素空间过重的问题，又比纯 latent WAM 有更好的结构。问题是 VGGT 本身不便宜，引入几何先验的计算代价是否超过了省去 pixel generation 的收益，摘要没有给出数字。LIBERO + real robot 组合评估算是标配了，看看精细任务上的数字是否真的超过 pixel-based WAM。 🔥

### 4. DynamicWAM: Dual-Path Motion Conditioning for World-Action Models in Dynamic Manipulation
- **作者**: Yunfan Lou, Hewen Gao, Xiyu Zhu, Zhuoran Qiao, Xuan Han, Yifan Yang, Yifan Ye, Boxian Yao, Zhibo Pang
- **机构**: 未知
- **链接**: [arXiv](https://arxiv.org/abs/2608.00793) | [PDF](https://arxiv.org/pdf/2608.00793)
- **来源**: 📄 arXiv 关键词检索

![](https://arxiv.org/html/2608.00793v1/x1.png)

- **核心方法**: 专为动态操作设计的紧凑 WAM。双路径：1）history-flow conditioning——用时序对齐的光流帧序列编码目标运动趋势；2）当前帧提供空间上下文。两路特征融合后输入 WAM 主干。不靠大型 backbone，而是靠 motion cue 增强感知。在 RealCore 数据集（动态操作场景）上有真实机器人实验。
- **对比方法/Baselines**: 与 [[OpenVLA]]、InternVLA、DynamicVLA 对比；PUMA/DOMINO 动态操作基准。
- **借鉴意义**: 光流作为运动条件的思路对于捡飞球、接物等动态任务有直接参考价值。
- **锐评**: 方向对，动态操作是 WAM 的真实痛点。光流 history 的想法不新鲜（各种 video prediction 都用过），但放进 WAM pipeline 并在真机上跑出来还是有价值的。担心的是：光流在遮挡或快速场景变化时噪声很大，dual-path 融合有没有 attention masking 或者其他鲁棒机制？摘要没提。另外 RealCore 数据集是自建还是公开？如果自建，复现性要打个问号。 👀

### 5. CoWAM: Coordination Contracts for Selective Policy Intervention with WAMs
- **作者**: Shuaijun Liu, Qifu Wen, Shuyang Hao, Qi Luo, Chenglong Zhang, Feiyang You, Chengyu Wu, Ningxin Su
- **机构**: 未知
- **链接**: [arXiv](https://arxiv.org/abs/2608.02578) | [PDF](https://arxiv.org/pdf/2608.02578)
- **来源**: 📄 arXiv 关键词检索

![](https://arxiv.org/html/2608.02578v1/x1.png)

- **核心方法**: WAM 预测的未来不一定要替换现有策略的动作——CoWAM 提出"协调合约"机制：当且仅当 WAM 候选未来满足同步性、角色兼容性、碰撞收敛性三个合约时，才干预原始双臂策略的动作。合约是 typed admissibility check + 事件条件验证 + 校准干预门的组合。基于 [[LeWorldModel]] 和 [[RDT]] 的双臂系统，在 [[RoboTwin]] + [[ALOHA]] 仿真测试。
- **对比方法/Baselines**: 与 LeWorldModel、RDT 作为 nominal policy；RoboTwin + ALOHA 仿真基准。
- **借鉴意义**: "WAM 作为选择性干预层而非主策略"这个角度有新意，对双臂协调任务有参考价值。
- **锐评**: 概念层面很有意思：不是让 WAM 替代策略，而是让 WAM 审核策略。但整篇只有仿真结果，真实双臂机器人上协调合约的 latency 和 false positive 率才是关键。三个合约的设计看起来需要人工定义，在复杂多样任务上的泛化能力存疑。仿真里的 precision 数字不能直接迁移到真机——这是最大硬伤。 ⚠️

### 7. ChainVLA: Chaining Vision-Language-Action Queries through a Unified Execution State for Long-Horizon Manipulation
- **作者**: Yuzhi Huang et al.
- **机构**: 未知
- **链接**: [arXiv](https://arxiv.org/abs/2608.02326) | [PDF](https://arxiv.org/pdf/2608.02326)
- **来源**: 📄 arXiv 关键词检索

![](https://arxiv.org/html/2608.02326v2/x1.png)

- **核心方法**: 1.2B 参数 VLA 策略，核心机制是 Unified Execution State（UES）——在每次 query 之间维护一个统一的跨 query 状态，同时保留两种信息：1）长期任务证据（类似 memory），2）短期动作连续性（action reuse + 状态更新）。解决的问题：现有 action-chunked VLA 每次 query 都从头 replan，既丢失历史上下文又有动作切换时的抖动。在 LIBERO + RoboMME 仿真基准上测试。
- **对比方法/Baselines**: 对比 [[SpatialVLA]]、[[OpenVLA]]、MemoryVLA、MemER、MemoAct；LIBERO + RoboMME 基准。
- **借鉴意义**: UES 的设计对于长时序任务（多步操作、需要记忆的场景）有直接参考价值。
- **锐评**: 想法成熟，把 memory 和 motion continuity 统一进一个 state 的角度比各自独立的方案更优雅。但最大硬伤：没有真机实验。LIBERO 做得好不代表在真实噪声环境下同样鲁棒，而 RoboMME 也是仿真。1.2B 参数在真机上的推理频率是否够用也没提。有了真机实验再来复议。 👀

### 8. Look Where It Matters: Adaptive Visual Refinement for Vision-Language-Action Models
- **作者**: Jin Cui et al.
- **机构**: 未知
- **链接**: [arXiv](https://arxiv.org/abs/2608.02197) | [PDF](https://arxiv.org/pdf/2608.02197)
- **来源**: 📄 arXiv 关键词检索

![](https://arxiv.org/html/2608.02197v1/x1.png)

- **核心方法**: AtVLA（Adaptive Token VLA）。发现 SigLIP/PaliGemma 等视觉编码器中存在 attention artifact patch（低信息区域吸收全局信息，污染密集空间特征），而且这个问题在 VLA post-training 阶段因为习得了 task-relevant 信息（物体位置、深度等）而被放大。解决方案：不确定性门控视觉精修——用不确定性估计识别 artifact patch，对这些 patch 做 task-relevant 的局部细化。在 SimplerEnv 仿真 + RTX 真实机器人上有实验。
- **对比方法/Baselines**: 基于 [[OpenVLA]]（PaliGemma backbone）、RowNorm；对比 SpatialVLA；SimplerEnv + RTX 真机。
- **借鉴意义**: 如果你在做基于 SigLIP/PaliGemma 的 VLA，attention artifact 问题很可能也影响你的模型。AtVLA 的诊断方法可以直接用来 debug 你的系统。
- **锐评**: 从已知的 ViT attention artifact 现象（Darcet 等人 2023 年发现的）到 VLA post-training 特异性放大的观察是有新意的。不确定性门控的方案也比简单的 patch dropping 更精细。有真机结果是可信度的保障。质疑点：不确定性估计的 overhead 是多少？在高频控制场景里，额外的前向 pass 是否引入不可接受的延迟？论文需要提供 latency breakdown。 👀

### 10. Hermite Curves as Trajectory Priors for Vision-Language-Action Models
- **作者**: Qi Lv, Jianming Xing, Zhao Yang, Mingyuan Yao, Yinan Shi, Yawei Jueluo, Mike Zheng Shou, Xiang Deng
- **机构**: NUS ShowLab, Harbin Institute of Technology (Shenzhen), Jiangsu Cytoderm Intelligent Technology
- **链接**: [arXiv](https://arxiv.org/abs/2608.01265) | [PDF](https://arxiv.org/pdf/2608.01265)
- **来源**: 📄 arXiv 关键词检索

![](https://arxiv.org/html/2608.01265v1/x1.png)

- **核心方法**: 把 action chunk 的轨迹参数化为**分段三次 Hermite 曲线**（由端点位置 + 导数定义），而不是逐时间步的离散控制序列。优势：1）曲线在端点处自然保证 C1 连续（位置和速度连续），消除 chunk 边界的抖动；2）参数量少（只需端点 + 导数），对隐式数据学习的依赖更小。VLA 输出曲线参数，在执行时采样恢复轨迹。在 LIBERO、WorldVLA、InternVLA 基准 + 真实机器人验证。
- **对比方法/Baselines**: 对比 [[FAST]]（token-based trajectory representation）、OpenVLA；LIBERO-10、SPARC 平滑度指标。
- **借鉴意义**: chunk 边界抖动是 VLA 实际部署的常见问题，Hermite 先验是一个轻量、有数学保证的解法。可以直接集成到现有 VLA 输出头。
- **锐评**: 技术方案干净，数学保证实在。C1 连续性对于高频控制来说是真实需求，不是噱头。与 FAST 的对比会是关键——FAST 用 token 离散化轨迹，Hermite 用连续参数，速度和精度的 tradeoff 是什么？另外，Hermite 曲线只保证端点处的连续性，中间段是否也足够平滑，取决于导数估计的准确性。 👀

### 15. The Gate, Not the Cache: Gate Provenance Bounds the Closed-Loop Reliability of Training-Free VLA Token Skipping
- **作者**: Qi Luo, Shuaijun Liu, Hao Zhao, Kunlin Li, Xiaobo Wang, Ningxing Su, Dongsheng Wang, Yun Chen
- **机构**: 未知
- **链接**: [arXiv](https://arxiv.org/abs/2608.00391) | [PDF](https://arxiv.org/pdf/2608.00391)
- **来源**: 📄 arXiv 关键词检索

![](https://arxiv.org/html/2608.00391v1/x1.png)

- **核心方法**: 分析训练无关的 VLA token 跳过加速（KV 缓存复用 vs token 剪枝）在闭环控制中的失效机制。核心发现：gate（决定哪些 token 要跳过）是从上一步加速后的前向传播中提取的，所以被跳过的 token 对下一步 gate 的贡献最弱，导致"哪些 token 值得跳过"的判断在闭环中会累积偏移，最终导致任务失败。在 [[OpenVLA]]、CogACT 和 AgileX 真实机器人上验证。
- **对比方法/Baselines**: 分析 KV 缓存方案和 pruning 方案；[[SIMPLER]] 仿真 + AgileX 真机。
- **借鉴意义**: 如果你在用 training-free token 跳过来加速 VLA 推理，这篇文章告诉你为什么它在闭环长任务里会翻车，是 debug 必读。
- **锐评**: 诊断很有价值，"gate 来自被加速的前向" → "gate 偏差累积"的逻辑清晰有说服力。真机实验也坐实了这个问题的实际影响。但论文停留在分析层面——没有提出解决方案，或者说"修这个 bug 的最简单方法是什么"。只分析不给修法，虽然有价值但贡献上限有限。 🫠

## 今日趋势

WAM 这个词今天出现了 8 次，已经到了"不叫 WAM 就不好意思投 cs.RO"的程度——这既是好事（社区在集中攻克视频-动作联合建模）也是坏事（质量参差不齐，跟风明显）。真正值得关注的两条线：一是 **DoT/轻量解耦架构**（Faster-WAM），解决的是真实部署的推理延迟问题；二是**几何感知 policy space**（SG-WAM），解决的是 latent WAM 缺乏物理结构的问题。全景 + 全身操作（PanoVLA、DreamTrajectory）的出现说明社区开始认真对待移动操作，不再局限于固定底座。触觉方向（FACT、ReTouch）在稳步推进，Stanford 的分析质量在，但不做真机是讲不完故事的。
